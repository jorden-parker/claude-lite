# cl flag collisions with claude

Checked against `claude` 2.1.322 (`claude --help`, plus probes with `-p` and no stdin) and the docs at https://code.claude.com/docs/en/cli-reference and https://code.claude.com/docs/en/settings-reference.

| :---------------------------- | :------------------------------------------------------ | :------------------------------------------------------------------------------------ | :----------------------------------------------------------------------------------------------------------------------------------------------- |
| `--think`                     | `cl ollama` intercepts (`src/ollama/size-overrides.ts`) | No. `unknown option '--think'`                                                        | Thinking is the `alwaysThinkingEnabled` setting and `MAX_THINKING_TOKENS` env (settings-reference).                                              |
| `--no-think`                  | intercepts                                              | No                                                                                    | Same as above. Setting `alwaysThinkingEnabled: false`.                                                                                           |

Docs also list `ultracode`, which the installed help does not. Collision: cl consumes it, so claude never sees it. |

## Answers to the extra questions

1. **`--`**: observed, not documented. `claude -- --version` treated `--version` as prompt text (the model answered instead of printing the version). `claude -p -- --effort bogus` did the same. So `--` ends option parsing and everything after it is positional prompt text. The CLI reference page has no sentence on `--`.
2. **Flags after the prompt**: observed, works. `claude hi --effort bogus -p` parsed `--effort` (it warned about the value). `claude hello --effort high --version` printed the version. The docs do not state this either way.
3. **Short flags**: claude has `-p`, `-c`, `-d`, `-n`, `-r`, `-v`, `-h`, `-w` (from `--help`). `-e` is `unknown option`. cl's source uses only long flags (no short flag found in `src/cli.ts`, `src/ollama/`). No short-flag collision.

## Notes

- Probing with `--help` tells you nothing: commander prints help even after an unknown flag. Use `-p` with no stdin and read the `unknown option` error instead.
- Repeated flags: for `--effort` the bogus-then-high probe warned only about `bogus`, so later wins. For `--model` the bogus-a-then-bogus-b probe warned only about `bogus-b`. Both point to last-wins, which is inferred from the warnings.
- Docs drift: the CLI reference lists `ultracode` as an `--effort` value. Installed 2.1.322 help does not. Hidden or newer features may exist beyond the installed build.
- The `--think`, `--sandbox`, `--permissions`, `--print-config`, `--ollama`, `--size` and `--local` names do not appear in the CLI reference page (grep of the full fetched text).
